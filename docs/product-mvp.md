# Продуктовая постановка MVP

## Цель продукта

Создать приложение для регулярного учета личных и семейных финансов, которое помогает пользователю видеть счета, операции, категории расходов и доходов, а также общий семейный бюджет в одном месте.

MVP должен доказать, что пользователь может вручную завести базовую финансовую картину: создать счета с понятными названиями, внести операции, вести общие и личные семейные счета и поделиться бюджетом со вторым участником семьи.

## Пользователи

- Личный пользователь, который ведет учет доходов, расходов, вкладов и брокерских счетов.
- Семейный пользователь, который хочет видеть общий бюджет с партнером или вторым членом семьи и разделять общие и личные счета.
- Второй участник семьи, которому нужен доступ к общим счетам, операциям и категориям без сложной настройки, а также собственные личные счета в семейной модели.

## Главные сценарии MVP

1. Пользователь регистрируется, входит в приложение и видит свое финансовое пространство.
2. Пользователь вручную создает или редактирует счета: наличные, банковский счет, вклад, брокерский счет, задавая тип счета и понятное название.
3. Пользователь вручную добавляет операции: доходы, расходы, переводы и базовые брокерские операции.
4. Пользователь вручную заполняет и исправляет операции: дату, сумму, счет, категорию, описание.
5. Пользователь различает общие семейные счета и личные счета участников семьи.
6. Пользователь настраивает категории доходов и расходов, включая название и иконку.
7. Пользователь приглашает второго участника семьи и открывает ему доступ к общему семейному бюджету.
8. Пользователь смотрит базовые отчеты по доходам, расходам, категориям и остаткам за период на Android и в PWA/браузере.
9. Пользователь может вручную проверить capture draft, созданный из выбранного им скриншота через OCR: на Android распознавание выполняется on-device без загрузки скриншота, в PWA/iOS browser скриншот временно отправляется на self-hosted backend OCR; операцию можно исправить или отклонить, а создание происходит только после подтверждения.

## MVP

- Авторизация и учетные записи пользователей.
- Базовая модель семьи: создание семейного пространства, приглашение второго пользователя, общие и личные счета.
- Счета: банковские, наличные, вклады, брокерские, с ручным заданием названия счета.
- Ручной ввод и редактирование счетов и операций.
- Операции: доходы, расходы, переводы, базовые операции по брокерскому счету без налоговой аналитики.
- Настраиваемые категории с иконками.
- Android-фронт.
- Браузерный вариант/PWA, пригодный для использования на iPhone.
- Базовые отчеты: доходы/расходы по периодам, расходы по категориям, остатки по счетам.
- Простой интуитивный интерфейс для регулярного учета.
- User-initiated capture drafts из выбранного пользователем скриншота: Android использует on-device OCR без загрузки скриншота; PWA/iOS browser использует временную загрузку скриншота на self-hosted backend OCR. В обоих режимах создается только pending draft без автосоздания операций.

## Не-MVP / Post-MVP

- Реальный parser pipeline для импорта Excel/CSV/файлов из банков, брокеров и других источников: загрузка/хранение по отдельной policy, разбор содержимого, preview diff, подтверждение изменений, audit и retention/deletion.
- Распознавание источника, счета и типа отчета для поддержанных форматов файлов.
- Экран проверки и корректировки импортированных операций.
- SMS/push-import pipeline, перехват SMS, перехват push/notifications, массовая поддержка банковских шаблонов и прямые банковские API.
- Уведомления и напоминания.
- Массовая поддержка всех банков, брокеров и форматов отчетов.
- Налоговая аналитика.
- Инвестиционные рекомендации.
- Продвинутая аналитика портфеля.
- Детальные роли и приватность внутри семьи beyond общего семейного пространства.
- Выбор коммерческой модели SaaS/self-hosted.
- Глубокая проработка юридических требований и юрисдикций.

## Допущения

- На старте продукт можно проектировать как веб-сервер с Android-клиентом и PWA/браузерным клиентом без выбора конкретного стека.
- Для MVP достаточно ручного ввода счетов и операций; источники импорта выбираются после MVP.
- Семейный доступ в MVP означает общий бюджет для двух пользователей с поддержкой общих и личных счетов, но без сложных ролей.
- Product invariant: personal всегда приватен. Personal-счета, personal-операции, personal-категории и personal-агрегаты другого участника семьи не раскрываются в MVP ни в списках, ни в отчетах, ни в поиске, ни через API-ошибки, логи или audit.
- В MVP есть два явных режима отчетов: `shared family report` строится только по общим семейным счетам, операциям и категориям household; `combined viewer overview` строится по общим семейным счетам household и personal-счетам текущего пользователя без personal-данных второго участника.
- Ручное редактирование счетов и операций является обязательной частью MVP.
- Брокерские операции в MVP нужны для учета факта операции и движения денег, а не для налоговых расчетов или рекомендаций.
- File import/report-preview не присутствует в MVP: пользователь не выбирает файл отчета, приложение не показывает preview/summary-placeholder и не передает содержимое файла в parser. Реальный импорт файлов требует отдельного parser pipeline, security review и privacy review до появления в продукте.
- Приложение не перехватывает SMS, push-уведомления или системные notifications и не использует SMS receiver / Android notification listener для создания операций.
- OCR из выбранного пользователем скриншота зависит от платформы: Android выполняет распознавание локально/on-device без загрузки скриншота; PWA/iOS browser временно загружает PNG/JPEG/WebP на self-hosted backend OCR. Backend не хранит скриншот или raw OCR text; сохраняются только structured capture draft, `idempotencyKey`/`evidenceHash` для дедупликации, hash-only category mapping и статус жизненного цикла `pending`/`confirmed`/`discarded`.
- Подтвержденный draft создает обычную manual transaction с теми же правилами доступа, редактирования, отчетов, audit и log redaction, что и ручной ввод.
- Ограничения OCR capture drafts: parser confidence не гарантирует точность, production deploy в рамках этой документации не подтвержден, bank API не подключаются.

## Критичные открытые вопросы

### Блокирующие для следующей волны

- Нет блокирующих вопросов по границам MVP после решения о ручном вводе и наличии общих/личных счетов.
- P1-01 closed: personal-only видимость подтверждена как продуктовый инвариант MVP.
- P1-02 closed: report modes разделены на `shared family report` и `combined viewer overview`.

### Неблокирующие для MVP-скоупа

- Будет ли продукт SaaS, self-hosted или гибридным.
- Какая юрисдикция и комплаенс-модель потребуются для публичного запуска.
- Нужны ли Android-приложение и PWA одновременно в первом техническом инкременте или один клиент может быть первым.
- Какие Excel/CSV/файловые или API-интеграции приоритетны после user-confirmed draft flow.

## Acceptance Criteria MVP

- Пользователь может зарегистрироваться, войти и выйти из аккаунта.
- Пользователь может создать семейное пространство и пригласить второго пользователя.
- Пользователь может создать основные типы счетов: банковский, наличные, вклад, брокерский.
- Пользователь может вручную задать и изменить название счета.
- Пользователь может различать общие семейные счета и личные счета участников семьи.
- Пользователь может вручную создать операцию и заполнить ключевые поля: дату, сумму, счет, категорию, описание.
- Пользователь может вручную изменить ключевые поля операции: дату, сумму, счет, категорию, описание.
- Пользователь может создать, переименовать и выбрать категорию с иконкой.
- Пользователь может видеть базовые отчеты по доходам, расходам, категориям и остаткам за выбранный период в режимах `shared family report` и `combined viewer overview`.
- Основные сценарии доступны на Android и в PWA/браузере для iPhone.
- MVP не включает Excel/CSV/файловый импорт, SMS/push/API-интеграции, перехват SMS/push/notifications, налоговую аналитику, инвестиционные рекомендации и массовую поддержку всех источников; capture drafts допускают только явное подтверждение пользователя перед созданием операции.
