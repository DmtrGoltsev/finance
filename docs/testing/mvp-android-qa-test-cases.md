### TC-GEN-001: Восстановление сессии при запуске приложения `[API]`
**Приоритет:** P0  
**Предусловия:** Токен сохранён в SecureTokenStore  
**Шаги:**
1. Запустить приложение
2. `LaunchedEffect` вызывает `restoredFinanceUiState()`
**Ожидаемый результат:** `sessionStatus()` → если authenticated → `dashboard()`. UI переходит к дашборду без показа логина.  
**Тип:** Positive  

### TC-GEN-002: Восстановление сессии — просроченный токен `[API]`
**Приоритет:** P0  
**Предусловия:** Токен сохранён, но просрочен  
**Шаги:**
1. Запустить приложение
2. `sessionStatus()` возвращает 401
**Ожидаемый результат:** Токен очищен. Показана карточка логина.  
**Тип:** Negative  

### TC-GEN-003: Автозагрузка capture drafts при авторизации `[API]`
**Приоритет:** P1  
**Предусловия:** Только что авторизовались  
**Шаги:**
1. Успешный логин
2. Проверить вызов `listCaptureDrafts(status="pending")`
**Ожидаемый результат:** `LaunchedEffect(isAuthenticated)` загружает pending drafts.  
**Тип:** Positive  

### TC-GEN-004: Переключение между вкладками навигации `[UI]`
**Приоритет:** P2  
**Предусловия:** Авторизован  
**Шаги:**
1. Последовательно нажать все 5 вкладок (Home, Operations, Assets, Categories, Analytics)
**Ожидаемый результат:** Контент переключается мгновенно. `selectedSection` обновляется. Подзаголовок в TopAppBar меняется.  
**Тип:** Positive  

### TC-GEN-005: FAB доступен на всех экранах `[UI]`
**Приоритет:** P2  
**Предусловия:** Авторизован  
**Шаги:**
1. Переключаться между вкладками
2. Проверять видимость FAB "+"
**Ожидаемый результат:** FAB отображается на всех экранах. Нажатие открывает QuickAddSheet.  
**Тип:** Positive  

### TC-GEN-006: Обработка сетевой ошибки при загрузке дашборда `[API]`
**Приоритет:** P1  
**Предусловия:** Нет сети  
**Шаги:**
1. Выполнить действие, вызывающее `loadDashboard()`
**Ожидаемый результат:** `ApiResult.Failure` → `userFacingMessage()`. Loading снимается. UI не крашится.  
**Тип:** Negative

## NEEDS_CLARIFICATION — Открытые вопросы

### NC-001: Фильтрация категорий по type/mode в CategoryManagementCard
**Описание:** В UI `CategoryManagementCard` есть переключатели type (Расход/Доход) и mode (Личное/Общее), но `visibleCategories` фильтрует только по `status == "active"`, не учитывая выбранный type и mode. Используется ли это для фильтрации отображения или только для создания новой категории?  
**Местоположение:** `FinanceApp.kt:1960-1989`  

### NC-002: Транзакции transfer — фильтрация по mode
**Описание:** `TransactionSummary.matchesMode()` для transfer требует `accountId in accountIds && counterpartyAccountId in accountIds`. Если один из счетов личный, а другой общий, перевод не покажется ни в Personal, ни в Shared. Это ожидаемое поведение?  
**Местоположение:** `FinanceApp.kt:2689-2697`  

### NC-003: Ограничение длины имени (80 символов)
**Описание:** `createAccount` и `createCategory` обрезают имя через `name.trim().take(80)`. Но в UI нет ограничения ввода. Пользователь может ввести >80 символов, UI покажет полное имя, но сервер сохранит обрезанное.  
**Местоположение:** `ApiClient.kt:376, 441`  

### NC-004: Валюта для перевода — fallback
**Описание:** `transferPairValidationMessage` запрещает перевод между разными валютами. Но нет явного указания, что произойдёт при валютной конвертации в будущем.  
**Местоположение:** `FinanceApp.kt:2709-2710`  

### NC-005: Restore API для счетов/категорий
**Описание:** ApiClient имеет `restoreAccount` и `restoreCategory`, но в UI нет кнопок восстановления. Архивированные сущности можно восстановить только через API.  
**Местоположение:** `ApiClient.kt:50, 62`  

### NC-006: Report summary только для household
**Описание:** `reportData` (totals) загружается только если `session.householdId != null`. Для пользователей без household нет report data.  
**Местоположение:** `ApiClient.kt:297-312`
