# Диагностика схемы production Finance

Этот workflow только читает известные признаки на хосте через закреплённый SSH
host key. Он не копирует файлы на хост, не вызывает Compose `up`, не меняет
службы, БД, сети, тома или указатели релизов. В журнал и артефакт попадают
только фиксированные признаки и проверенные имена текущих релизов; значения
переменных окружения и параметры контейнеров не выводятся.

Запуск ограничен владельцем репозитория, точной веткой
`codex/finance-prod-inventory-20260922` и подтверждением
`finance-readonly-inventory`. Рабочий процесс использует существующие секреты
окружения `production` с `StrictHostKeyChecking=yes`; `deployment: false`
исключает создание записи о развёртывании.

**Текущий барьер:** окружение `production` допускает только ветки
`prod/release-*`. Поэтому этот non-release workflow после публикации ветки и
слияния PR в `main` не получит доступ к окружению и не выполнит инвентаризацию.
Не отправлять диагностический commit в release-ветку и не отключать защиту
веток ради запуска. Владелец должен отдельно утвердить безопасный доступ этой
единственной диагностической ветке либо предоставить иной утверждённый
read-only канал. Изменение политики окружения в рамках этого PR не выполняется.

Признак `*_writable=yes` означает только права текущего SSH-пользователя на
указанный существующий каталог, а не разрешение устанавливать там сервис.
Признаки наличия переменной проверяют её имя, не пригодность значения. Проверка
сети из контейнера в host backend не выполняется: запуск временного контейнера
или изменение сетевой конфигурации не относятся к read-only инвентаризации.
