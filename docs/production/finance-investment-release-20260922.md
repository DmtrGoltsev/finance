# Подготовка выпуска инвестиционных рекомендаций Finance

Состояние: локальный Docker-контракт сохранён лишь как прототип. Release branch
не отправлена, production не изменён. После preflight PR #11 Docker-путь
отключён: `production-package-gate` безусловно выдаёт
`DELIVERY_HOST_NATIVE_CAPACITY_UNVERIFIED` **до обращения к хосту**, включая
release push и ручной dispatch. Старые approval variables не снимают блокировку.
Host-native installer пока не реализуется: доказательств ёмкости и изоляции БД
недостаточно. Перечень необходимых фактов находится в
[`HOST_NATIVE_READINESS.md`](../../ops/finance-release/HOST_NATIVE_READINESS.md).

## Что сохранено как локальный прототип

- Docker Engine и Compose устанавливаются только на точно совпавшем с
  утверждённым inventory Debian/Ubuntu, из заранее настроенного официального
  apt-источника и с точными версиями всех пяти пакетов. Иначе стадия отказывает.
- Отдельный Compose-проект Finance содержит PostgreSQL, n8n и gateway. Образы
  PostgreSQL, n8n и базовый образ gateway закрепляются digest. Только редактор
  n8n слушает loopback; PostgreSQL и gateway не публикуют портов.
- Worker запускается как служба systemd от `finance`; callback gateway
  проходит узкий proxy на адресе Docker bridge к существующему
  `127.0.0.1:8081`. Контур не подключается к AgentSystem и не открывает
  публичный webhook/API.
- Секреты один раз генерируются вне Git с правами `0600`. До установки
  проверяется наличие внешних DeepSeek и FCM секретов. Импортируется один
  Header Auth credential и ровно три workflow; включение происходит только
  после миграций и переключения backend на тот же release ID.
- Обе новые БД резервируются, проверяются SHA-256 и восстанавливаются в
  изолированные временные БД. Есть отдельные команды health, restore и
  rollback; тома и финансовая БД автоматически не удаляются.

Полный порядок, поля approval, имена секретов и границы автоматизации:
[`ops/finance-release/README.md`](../../ops/finance-release/README.md).

## Блокеры снятия gate

1. Read-only preflight из PR #11 (`main`
   `afab10759c482b41af37c102c5c2901b82d5ea64`) подтвердил Ubuntu 26.04
   x86_64, backend от `finance`, health на `127.0.0.1:8081` и отсутствие Docker.
   Доступно 2 126 744 KiB памяти и 3 530 780 KiB места на `/opt` и `/var/lib`.
   Контракт требует минимум 3072 МБ и 8192 МБ соответственно. Нужны план
   ёмкости и новый inventory; снижать пороги по предположению нельзя.
2. Не подтверждены точная host-native версия/источник Node, размер установки
   n8n 2.39.8, права на отдельные роли/БД PostgreSQL, занятость loopback
   портов `8080` и `8091` и право CI-пользователя на `sudo -n`. Свободный
   `5680` сам по себе не подтверждает сетевой план. Нужны approval и рабочее
   окно.
3. Нет внешних DeepSeek/FCM credentials, тестового bearer token и UUID
   подтверждённого снимка. Их presence gate действует до установки; после
   активации обязателен сквозной job/report тест. Доставку FCM на устройство
   проверяют отдельно.
4. Если отказ произойдёт после переключения backend, нужен операторский
   план отката и доказанный доступ к резервной копии основной БД Finance.

До закрытия этих блокеров не сливать PR как разрешение на развёртывание, не
публиковать release branch и не запускать production deploy.
