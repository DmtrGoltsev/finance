# Контур рекомендаций Finance в n8n

Изолированный локально проверяемый контур для отложенного анализа инвестиционного портфеля. Он подготовлен на основе действующих практик N8NAgents, но не содержит OpenClaw, Telegram, Poruchik и не меняет существующие процессы AgentSystem.

## Граница ответственности

- Finance backend остаётся единственным источником истины для портфелей, заданий, статусов и рекомендаций.
- n8n принимает только нормализованные обезличенные позиции с `SECID/ISIN`.
- n8n собирает сведения с фиксированных официальных адресов, вызывает DeepSeek и возвращает подписанный результат.
- n8n не получает исходные скриншоты, ФИО, номера счетов и идентификатор владельца.
- Сделки не выполняются. Итог предназначен только для ручного решения владельца.
- Push создаётся backend Finance после принятого callback; этот контур FCM не вызывает.

## Состав

- `compose.yml` — отдельные n8n `2.39.8`, PostgreSQL, сети, тома и ограничения ресурсов.
- `workflows/` — три неактивных при импорте процесса: анализ, подписанная проверка готовности и очистка метаданных.
- `runtime/` — исходный код узлов n8n; экспорт собирается детерминированно.
- `postgres/init/` — технический реестр дедупликации без содержимого портфеля.
- `policies/source-allowlist.json` — разрешённые источники и выключенные новостные ленты.
- `scripts/` — сборка, проверка, health, backup, restore drill и rollback.
- `tests/` — проверки HMAC, SSRF, приватности payload и ответа модели.

## Локальная проверка

```powershell
cd ops/finance-n8n
npm run build:workflows
npm test
npm run validate
npm run smoke
```

`npm run smoke` использует только синтетические секреты, временный Compose project и временные тома. Он не обращается к VPS, Finance backend, DeepSeek или рыночным источникам.

## Импорт без активации

1. Создать `.env` из `.env.example` и установить права только владельцу.
2. Создать внешнюю внутреннюю Docker-сеть `finance_backend_internal` и подключить к ней только Finance backend и Finance n8n.
3. Выполнить `docker compose up -d --wait`.
4. Импортировать JSON из `workflows/`. Все процессы импортируются неактивными.
5. Создать credential `Finance n8n PostgreSQL` для отдельной БД этого контура и назначить его PostgreSQL-узлам.
6. Выполнить `n8n audit`, локальный health и подписанную прикладную проверку.
7. Активировать сначала health и retention, затем основной процесс.

Редактор доступен только через `127.0.0.1:5680` или SSH-туннель. Caddy обязан отвечать `404` на `/webhook/internal/finance/*`.

## Внешние предпосылки production

Потребуются значения, которые нельзя сохранять в Git:

- отдельный пароль роли PostgreSQL Finance n8n;
- отдельный `N8N_ENCRYPTION_KEY`;
- независимые `FINANCE_INGRESS_HMAC_SECRET` и `FINANCE_CALLBACK_HMAC_SECRET`;
- `DEEPSEEK_API_KEY` и подтверждённое имя доступной модели;
- учётная запись владельца n8n и второй фактор;
- закрытое резервное хранилище с правом записи без права удаления у runtime.

Потребуются разрешения:

- создание отдельных Docker network/volume/container на VPS;
- подключение Finance backend к `finance_backend_internal`;
- исходящий HTTPS только к DeepSeek и разрешённым официальным источникам;
- изменение приватной конфигурации Caddy для явного `404` внутренних путей;
- создание backup и проведение restore drill в изолированной БД;
- настройка планового запуска backup и проверки retention.

Backend-интеграция вне этой ветки: worker outbox должен подписывать канонический envelope для n8n и отмечать событие обработанным только после HTTP `202`. До появления и проверки этого worker production-активация основного workflow запрещена.

## Источники

По умолчанию включены только Московская биржа ISS, Банк России, Минфин России и ФНС России. IR-домены эмитентов добавляются код-ревью в allowlist. РБК, Интерфакс и ТАСС выключены до документированного лицензирования. Модель не выбирает URL и не может включить источник сама.

## Хранение

Содержимое успешных и ошибочных executions в n8n не сохраняется. Таблица `finance_analysis_runs` содержит только `event_id`, `job_id`, attempt, hash, состояние и безопасный код ошибки. Успех хранится 7 дней, ошибка 30 дней. Binary, скриншоты, состав портфеля, provider response и HMAC-заголовки в журнал не записываются.
