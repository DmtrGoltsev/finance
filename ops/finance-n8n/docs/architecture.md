# Архитектура внутреннего шлюза Finance

## Поток

1. Backend сохраняет задание и отправляет подписанную оболочку в закрытый webhook n8n.
2. Webhook с `responseMode=responseNode` передаёт исходные бинарные данные и три HMAC-заголовка в `/accept` шлюза.
3. Шлюз проверяет служебный токен, размер, подпись над сырыми байтами и возраст подписи до 300 секунд. Только затем разбирает JSON и проверяет точный контракт.
4. PostgreSQL блокирует операции конкретного `jobId`, проверяет nonce, `eventId`, хеш содержимого и номер попытки. Задание шифруется AES-256-GCM и сохраняется в отдельной БД шлюза. Только после COMMIT возвращается `202`.
5. Respond to Webhook возвращает статус шлюза. Раннего подтверждения нет. Потеря процесса n8n после этого не теряет принятое задание.
6. Каждую минуту n8n вызывает `/drain`; шлюз атомарно выбирает одну запись через `FOR UPDATE SKIP LOCKED`. Параллельный запуск не обрабатывает ту же запись.
7. Подписанные статусы `collecting`, затем `analyzing` предшествуют готовому результату. Данные рынка и ответ модели обрабатываются только шлюзом.
8. Результат шифруется и сохраняется до callback в Finance. После подтверждения содержимое удаляется, технические метаданные остаются 7 дней для успеха и 30 для ошибки. История пользователя хранится в Finance бессрочно.

## Идемпотентность и аварии

- `eventId` уникален; `(jobId,attempt)` уникален, attempt от 1 до 3. Точный повтор с новым nonce подтверждается без нового анализа; конфликт содержимого отклоняется.
- Повтор nonce отклоняется. Nonce хранится 10 минут, окно подписи 5 минут.
- Повторный доменный анализ допускается только после завершённой ошибки предыдущей попытки; n8n не создаёт новые попытки.
- HTTP-операции ограничены тремя попытками при временных сетевых ошибках. Постоянные ошибки, SSRF, перенаправления и некорректная схема не повторяются.
- Число попыток terminal callback хранится в БД, поэтому перезапуск не обнуляет лимит. После трёх неудач результат остаётся в `delivery_failed`, а не теряется и не генерируется снова.
- Прерванный анализ после истечения 60-минутного срока захвата переводится в ошибку; следующий запуск не повторяет незаметно обращение к модели. Восстанавливаемый сохранённый callback не запускает модель повторно.
- Ошибка ответа backend после фактического принятия требует сверки оператором: backend пока не имеет идемпотентного повторного подтверждения. Ложный успех при `409` запрещён.

## Сетевая защита

Рыночные URL выбирает код, не входной пакет и не модель. Разрешены только точные официальные страницы и пути ISS. До HTTPS-запроса разрешаются все DNS-адреса; любой частный, локальный, зарезервированный или IPv4-mapped ответ отклоняется. Соединение использует закреплённый проверенный адрес; повторного DNS-поиска при подключении нет. TLS проверяет исходное имя хоста, повторное использование соединений отключено. Перенаправления запрещены, лимит ответа 1 МиБ контролируется также при потоковом чтении.

DeepSeek использует тот же механизм проверки DNS/TLS. Единственное допустимое частное HTTP-направление: фиксированный callback Finance внутри закрытой Docker-сети. Секреты, URL и payload не выводятся в ошибки и журналы.

## Данные и модель

`marketDataAsOf` вычисляется как самое раннее официальное время среди использованных котировок MOEX: `SYSTIME` либо `TRADEDATE + UPDATETIME`. Время без зоны трактуется как московское `+03:00`. Время загрузки хранится отдельно как `fetchedAt` и никогда не заменяет время котировки. Отсутствующее, будущее или старше 24 часов время делает котировку непригодной; отсутствие свежих данных по любой позиции блокирует анализ.

Контекст ЦБ/Минфина/ФНС имеет `publishedAt=null`, если дата публикации не подтверждена. Такие страницы не определяют свежесть котировок. Новости выключены. Каждый вывод о рынке ограничен реально собранными источниками.

DeepSeek получает только проверенный пакет позиций, рыночный набор и детерминированный расчёт первоочередного использования свободных денег. Идентификаторы задания, владельца и счёта не отправляются. Строгая JSON Schema закрывает все объекты, включая фиксированные поля `assumptions`; AJV повторно проверяет результат без преобразования типов. Затем проверяются инструменты, три группы риска и суммы действий. Backend дополнительно проверяет финансовые инварианты.

## Изоляция

Finance, n8n и gateway не используют БД или credentials других проектов. У шлюза отдельная БД и роль внутри PostgreSQL данного контура. PostgreSQL и gateway не публикуют порты. n8n не имеет внешней сети выхода, Code/Execute Command отключены. Шлюз имеет отдельную сеть исходящего доступа и запускается непривилегированным пользователем с файловой системой только для чтения. Компоненты OpenClaw, Telegram и Poruchik отсутствуют.
