# Условия перехода на host-native поставку

Решение о развёртывании **не принято**. Проверенный preflight PR #11 на
`main` `afab10759c482b41af37c102c5c2901b82d5ea64` показал Ubuntu 26.04
x86_64, работающие nginx/PostgreSQL 18.6/backend, отсутствие Docker, около
2,13 ГиБ доступной памяти и 3,53 ГиБ свободного места. Backend слушает
`127.0.0.1:8081` от `finance`; Alembic имеет ревизию `20260822_0019`,
`public.outbox_events` нет. Это исходные факты, а не доказательство, что
n8n 2.39.8, gateway, worker и резервные копии поместятся на том же хосте.

## Недостающие доказательства

1. Замер пикового потребления памяти и диска n8n 2.39.8 на Node 22 либо 24,
   gateway и worker, включая установку зависимостей, миграции, обе БД и две
   резервные копии. Нужен утверждённый запас для PostgreSQL, nginx и backend,
   а также расположение `/opt` и `/var/lib` по файловым системам. При текущих
   2,13/3,53 ГиБ запуск не допускается по одному лишь расчёту «должно хватить».
2. Точная версия, источник, контрольная сумма и фактическое наличие Node/npm,
   совместимых с n8n 2.39.8. Пакетный источник и порядок восстановления без
   произвольного `npm install -g` на production должны быть утверждены.
3. Права утверждённого оператора PostgreSQL на создание **отдельных** роли и
   БД n8n, роли и БД gateway без изменения существующей Finance DB; версии
   `pg_dump`/`pg_restore`, доступное место для дампов и изолированная проверка
   восстановления. Размер текущей Finance DB и её резервной копии нужен до
   миграций `0019` → `0025`.
4. Свободные loopback-порты n8n `5680`, gateway `8080` и worker `8091`;
   отсутствие конфликтующих units; владелец каталогов/служб, `sudo -n` права
   Actions и точное правило сетевой изоляции. Свободный `8000` не заменяет
   проверку `8080` и `8091`. Публичные webhook и внутренний API запрещены.
5. Наличие вне Git ключа DeepSeek, FCM service account и тестового bearer
   token/подтверждённого snapshot UUID; реальные права провайдеров и сетевые
   маршруты. Одно наличие имён переменных в `backend.env` недостаточно.

## Обязательный контракт будущей реализации

- Сначала неизменяемый approval по свежему inventory, CI-пакеты и
  read-only preflight **до** какого-либо изменения хоста. Пока факты выше
  отсутствуют, `production-package-gate` всегда отказывает до SSH.
- Отдельные PostgreSQL БД/роли и файлы `0600` вне Git, точные версии Node/n8n,
  host-native systemd units от `finance`, n8n/gateway/worker только на
  loopback. Gateway должен передавать подписанный callback непосредственно на
  `127.0.0.1:8081`; Docker bridge и callback proxy не используются.
- Повторная стадия проверяет идентичность всех файлов и сохраняет ключи;
  импортирует один credential и ровно три workflow. До переключения backend
  нужны резервные копии новой и основной БД с SHA-256 и успешная пробная
  реставрация в отдельные БД. После переключения обязательны signed health,
  сквозной job/report и отдельная проверка FCM на устройстве.
- Сбой любой стадии не должен оставлять частично активированные workflow или
  новый worker. Откат должен работать при просроченном inventory и низкой
  памяти, сохранять ключи и данные и иметь явную процедуру возврата backend
  после миграций. До реализации и тестирования этих свойств deployment hold
  остаётся безусловным.

Нельзя принимать Docker-прототип из этого каталога за host-native installer.
Локальные Docker smoke-тесты проверяют только код gateway/n8n и не оценивают
вместимость production VPS.
