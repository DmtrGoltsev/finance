# Доставка инвестиционных рекомендаций

Отдельный процесс `python -m app.delivery.worker` использует основную БД Finance.
Миграция `20260920_0024` применяется перед запуском worker и новой версии API.
Сам worker не применяет миграции и не изменяет конфигурацию сервера.
Деплой в этой работе не выполнялся.

## Гарантии и ограничения

- Атомарный `UPDATE RETURNING` захватывает событие; PostgreSQL использует
  `FOR UPDATE SKIP LOCKED`. После истечения аренды другой процесс восстанавливает работу.
  Уникальный маркер аренды запрещает старому процессу подтверждать чужой захват.
- Событие анализа содержит постоянные `eventId`, `jobId`, номер доменной попытки и
  неизменяемый пакет. Транспортный повтор не создаёт новое задание и не увеличивает
  доменные три попытки. Для каждой передачи создаются новые timestamp/nonce/HMAC.
- Доставка n8n подтверждается только `202`, `accepted: true` и совпадающим `eventId`.
  Перенаправления запрещены, URL ограничен внутренним n8n и фиксированным путём.
  JSON подписывается до отправки; пересериализация после подписи запрещена.
- Повторы используют задержки 10, 20, 40 секунд и далее до часа. После 12 неудач
  событие остаётся в `dead`, а не теряется и не считается доставленным.
  В той же транзакции связанное задание в `queued` получает `failed` и
  `lastErrorCode=delivery_failed`; уже начавшийся анализ не перезаписывается.
  В Android появляется «Повторить доставку», используется защищённый авторизацией
  `POST /api/v1/investments/recommendation-jobs/{jobId}/retry-delivery`.
  Чужое задание возвращает 404, иной тип ошибки задания возвращает 409.
  Повтор восстанавливает **то же** событие и задание: сохраняет идентификаторы,
  `idempotency_key`, `deduplication_key`, пакет, дату создания и доменную попытку.
  Повторные нажатия не сбрасывают активную аренду или задержку. Новый запрос анализа
  при неразрешённом `delivery_failed` отклоняется с `DELIVERY_RETRY_REQUIRED` (409).
  Массовые SQL-правки не являются штатным интерфейсом.
- Gateway сохраняет компактные записи идентичности событий без ограничения срока,
  даже после удаления содержимого через 7/30 дней. Потеря ACK не запускает повторную
  генерацию. Для `delivery_failed` gateway возобновляет только сохранённый обратный
  вызов. Если он уже удалён по сроку хранения, возвращает `DELIVERY_RESULT_EXPIRED`
  и не генерирует новый результат; требуется разбор оператором.
  Дата события остаётся исходной даже после долгого простоя. Свежесть HMAC по-прежнему
  проверяется по подписанному timestamp и nonce; рыночные данные проверяются отдельно.
- Для каждого устройства сохраняется отдельная запись `(event_id, device_id)`.
  Успешно подтверждённые отправки повторно не отправляются. `UNREGISTERED` от FCM
  удаляет токен; общая `INVALID_ARGUMENT` не удаляет потенциально исправный токен.
- FCM не предоставляет идемпотентный ключ отправки. При потере ответа Google возможна
  повторная передача тех же данных. Android хранит `eventId` 35 дней, использует
  стабильный тег уведомления и подавляет повторный сигнал. Абсолютная гарантия
  доставки ровно один раз невозможна. Падение между сохранением маркера и показом
  может потерять уведомление; сам отчёт остаётся доступен в серверной истории.
- Push содержит только тип, идентификаторы события/задания/сессии, внутреннюю ссылку
  и нейтральное «Анализ портфеля готов». Ни сумм, ни названий бумаг в нём нет.
  Уведомление старой сессии после выхода или смены пользователя отбрасывается.
- Регистрация привязана к владельцу и действующей сессии. Выход и отзыв всех сессий
  удаляют токены в той же транзакции. API другого владельца не может захватить устройство.
  Устройства без обновления 270 дней не участвуют в доставке.
- Номер сессии не является токеном доступа. Google service account и OAuth2-токены
  хранятся только в памяти процесса или внешнем файле/переменной окружения.
  Исключения транспорта, тела запросов и токены не выводятся в журналы.

## Настройка и запуск

Рабочий env-файл и каталог секретов находятся вне Git. Шаблон: `.env.example`.
`FINANCE_BACKEND_DATABASE_URL` должен вести в БД Finance с правами на outbox,
регистрации, сессии, каталог и позиции. n8n/gateway используют свои отдельные БД.
`FINANCE_BACKEND_DELIVERY_INGRESS_SECRET` равен ключу входа gateway,
но **не** ключу обратного вызова или служебному токену n8n.

Для Compose задать внешние пути `FINANCE_DELIVERY_ENV_FILE` и
`FINANCE_DELIVERY_SECRETS_DIR`, затем выполнить `docker compose -f compose.yml config --quiet`.
Контейнер не публикует порты. Подключается к существующей `finance_backend_internal`
и отдельной сети исходящего трафика. Вход n8n должен быть активирован после импорта.
При неконтейнерной установке тот же entrypoint можно запускать отдельной службой,
задав внутренний URL n8n на localhost и доступ к основной БД.

`/healthz` и `/metrics` на внутреннем порту 8091 не содержат данных портфеля.
При остановленном цикле или ошибке БД здоровье становится отрицательным через 90 секунд.
Счётчики: `claimed`, `processed`, `failed`, `dead`, `delivery_errors`,
`database_errors`, `invalid_tokens`, `catalog_refreshed`, `catalog_errors`.
SIGTERM/SIGINT прекращает новый захват, заканчивает текущую передачу и закрывает
соединения. Незавершённые аренды восстановит следующий worker.

### Откат миграции

Перед откатом `0024` остановить все worker-процессы. Downgrade переводит
`processing` в `pending` с текущим `available_at` **до** удаления полей аренды.
Идентификаторы и содержимое outbox сохраняются. После повторного upgrade событие
снова захватывается, gateway использует прежний ключ защиты от дублей.
Откат удаляет таблицы регистрации устройств и доставки push; после upgrade
понадобится повторная регистрация устройств. Откат не является штатным способом
повторной отправки уведомлений.

### Контекст Docker

Сборка использует корень репозитория и Dockerfile
`ops/finance-delivery/Dockerfile`. Его специальный файл
`Dockerfile.dockerignore` закрывает весь контекст, затем разрешает только
`pyproject.toml`, backend `README.md` и исходники `.py` из `apps/backend/src`.
Дополнительные запреты исключают `.env*`, credentials/service-account, ключи,
`google-services.json`, Git, виртуальные окружения и кеши даже внутри исходников.
`COPY` ограничен манифестом и исходниками; миграции worker не запускает.
Рабочие секреты монтируются только во время запуска, никогда при сборке.
Тест проверяет этот разрешающий список и инструкции COPY, но без запуска Docker
не подтверждает фактическое содержимое собранного образа.

## Справочник MOEX

Каждые пять минут проверяется срок записей. Инструмент обновляется после 12 часов,
до истечения TTL 24 часа. Используются SECID уже известных инструментов, сохранённых
позиций портфелей и дополнительного списка `FINANCE_BACKEND_MOEX_REFRESH_SECIDS`.
PostgreSQL advisory lock сериализует обновление между worker-процессами.
Ошибка одной бумаги не блокирует остальные. Ручная команда
`python -m app.ops.refresh_moex_catalog --secid SBER` сохраняется;
для production у неё по-прежнему требуется `--confirm-production`.

## Android и внешние данные Firebase

Обычная локальная сборка: `-PfinancePushEnabled=false` (значение по умолчанию).
`google-services.json` не нужен, Firebase не инициализируется, серверная история
и ручное обновление доступны. Исходники настоящего `FirebaseMessagingService`
при этом компилируются, поэтому отключение push не скрывает ошибки компиляции.

Для сборки с push нужны четыре внешних Gradle-свойства из Android-приложения
Firebase с package `com.finance.mvp`:

1. `firebaseApplicationId`: `mobilesdk_app_id`.
2. `firebaseApiKey`: Android API key, ограниченный приложением согласно политике проекта.
3. `firebaseProjectId`: идентификатор Firebase project.
4. `firebaseSenderId`: числовой project number / sender ID.

Передать их через пользовательский Gradle properties или защищённый CI вместе с
`financePushEnabled=true`. При пропуске любого поля конфигурация сборки отклоняется.
Приложение инициализирует `FirebaseOptions` напрямую, плагин google-services не нужен.
Не коммитить рабочие значения, `google-services.json` или service-account JSON.

Для backend нужны `FINANCE_BACKEND_FCM_ENABLED=true`, тот же project ID и JSON
**отдельного** service account с правом `cloudmessaging.messages.create`, включённым
FCM HTTP v1 API. JSON передаётся read-only файлом `FINANCE_BACKEND_FCM_CREDENTIALS_FILE`
либо секретом `FINANCE_BACKEND_FCM_CREDENTIALS_JSON`, не обоими одновременно.
В Android этот JSON и закрытый ключ не попадают.

Для настоящего сквозного теста дополнительно нужны устройство/эмулятор с Google Play
services, разрешение уведомлений Android 13+, сеть до Google OAuth2/FCM, работающие
Finance API и n8n/gateway. Если Android API key ограничен сертификатом приложения,
в консоли Firebase/Google нужно разрешить SHA-1/SHA-256 используемой подписи APK.
Регистрация обновляется при входе, запуске приложения, смене токена и раз в сутки.
После выхода смена токена откладывается до следующего подключения; старые сообщения
подавляются сразу по отсутствию/смене сессии.

## Проверки

`python -m pytest tests/delivery -q` выполняет конкурентный захват, восстановление
аренды, повторы, ack/HMAC, ownership/logout, FCM invalid token, частичный успех
нескольких устройств и одиночное плановое обновление MOEX.
Также проверяются остановка зависшего задания, авторизация повторной доставки,
сохранение ключей, два конкурентных повтора, потерянный ACK, реальное выполнение
функций downgrade→upgrade→claim и ограничение контекста Docker.
Без дополнительных настроек это SQLite и подставные n8n/FCM.
`FINANCE_DELIVERY_TEST_POSTGRES_URL` включает тот же набор на PostgreSQL во временной
схеме. CI поднимает отдельный PostgreSQL только для тестов; production DSN запрещён.
Docker был недоступен локально, поэтому локальная успешная SQLite-проверка не является
доказательством настоящих PostgreSQL-гонок или доставки FCM на телефон.
