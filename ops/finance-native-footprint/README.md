# Замер места для нативного контура Finance

Workflow `.github/workflows/finance-native-footprint.yml` измеряет затраты на
временном GitHub-hosted Ubuntu 24.04 runner. Он не обращается к Finance VPS,
не использует production environment, SSH, Docker и секреты. PR запускает
только проверку контракта. Ручной замер допускается исключительно на `main`
владельцем репозитория и требует точного SHA текущей вершины ветки
`codex/investment-recommendations-ci-20260923`; иной SHA отклоняется до
загрузки feature-кода. До публикации обновлённого SHA ручной запуск запрещён.

Из собственного закреплённого lockfile workflow устанавливает `n8n@2.39.8`
через `npm ci`. Из указанного feature-коммита он берёт lockfile и исходники
gateway (`ops/finance-n8n`) и Python-пакет worker (`apps/backend`). Отдельный
lockfile Python-зависимостей в текущем feature-коммите отсутствует: worker
устанавливается из `pyproject.toml`, а хеш итогового списка версий фиксируется
в артефакте. Изменение этого списка при следующем замере означает, что
результаты напрямую несопоставимы.

На том же временном разделе находятся архив и распакованная копия Node
22.22.1, npm 9.2.0, оба npm install, Python venv, npm cache и полная копия
stage для rollback. Временный `HOME` также находится на измеряемом разделе,
чтобы побочные cache-записи install-скриптов не выпадали из расчёта.
Node-архив сверяется с опубликованным SHA-256. Скрипт
снимает свободные байты и inode каждые 200 мс; разность между началом и
минимумом есть **наблюдавшийся**, но не гарантированный абсолютный пик:
краткий всплеск между отсчётами может быть пропущен. Измерение также включает
побочные записи самого runner на общем разделе. `du -sB1` даёт занятые блоки
компонентов после установки; их нельзя складывать с наблюдавшимся пиком как
независимые расходы.

Только фиксированные числовые поля и SHA-256 публичных файлов попадают в
артефакт после строгой проверки. Исходники, содержимое cache, имена файлов,
вывод npm/pip и значения переменных окружения не публикуются. При ошибке
установки workflow завершится без артефакта с непроверенными числами.

Для сопоставления с VPS от последнего проверенного свободного места
`3 615 506 432` байта отдельно удерживаются `1 227 784 192` байта под
backup и выпуск. Остаток `2 387 722 240` байт можно сравнивать с
наблюдавшимся пиком только после успешного замера. Это не доказательство
вместимости при другом Linux, версии зависимостей, размерах исходников,
количестве rollback-копий или неуловленном кратком пике.
